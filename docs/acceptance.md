# 受け入れ条件と E2E シナリオ

機能凍結（11/6 正午）までに全項目を満たす。チェックは `qa-tester` が Playwright で自動化し、手動確認が必要なものは `docs/reviews/` に記録する。

## 1. 受け入れ条件（チェックリスト）

### 使い始め
- [ ] 「サンプル施設で試す」を押すと、入力なしでボードが開く（架空の「ひまわり苑」）。
- [ ] 自分の施設は、施設名＋グループ・利用者の貼り付け・職員の貼り付けの3ステップで登録できる。失敗行は行番号と理由が出る。
- [ ] 初期設定と日々の設定が分かれている。

### 時間割と配置
- [ ] 個別（対象1名）・一括（対象複数）・共通（対象なし）・休憩が同じボードに出る。
- [ ] 一括業務の対象者一覧を開いて確認できる（人数だけではない）。
- [ ] 必要人数と割当数の差が「担当未定」「担当あと n 人」で出る。充足は無印。多い場合は「n人 多め」。
- [ ] D&D（職員チップ→カード）で割当でき、タップ（＋ 担当を追加→候補）でも同じ結果になる。
- [ ] 候補は 問題なし／注意／勤務外・休み の3段で、全員に理由が一文付く。
- [ ] 重複・勤務外・休憩・条件不一致・初回のみ は警告して許可。二重登録はできない。
- [ ] すべての変更がトーストで分かり、「元に戻す」で戻る（10手）。
- [ ] 長押し／右クリックで 中止・ずらす・担当を外す ができる。
- [ ] 時刻のドラッグ変更は存在しない（メニューのみ）。
- [ ] ボード右上に「更新 hh:mm」（時刻のみ）。
- [ ] 職員ビューで重なり・勤務前後・休憩・見守りの空きが見える。

### 朝の流れ
- [ ] 出勤者に役割を付け、型を当てると、役割に束ねた業務に担当が付く。
- [ ] 介護助手を「休み」にすると、その役割の枠が「担当未定」になる。
- [ ] 「できました」に枠数・担当が付いた数・担当未定と担当あと n 人の一覧が出る。
- [ ] 「今日の形を型として保存」で時刻・役割・必要人数だけが保存される（人は保存されない）。

### 手元画面
- [ ] ボードで変えた担当が、別端末（同期）または別タブ（ローカル）のマイナビに反映される。
- [ ] 「いまの時間の予定」という見出しで、「実施中」「完了」「済」の語がどこにもない。
- [ ] 時刻が過ぎた予定を自動で完了扱いにしない（薄く表示するだけ）。
- [ ] 業務詳細に お願いすること／しないこと・場所・対象者・一緒に・手順・物品・相談先 が出る。
- [ ] 手元画面の利用者名が表示名モードに従う（既定: 部屋番号＋姓）。ボードはフルネーム。
- [ ] 共有端末モードで職員を切り替えられる。
- [ ] リーダーのスマホで クイック操作3種 がプレビュー→適用で動き、3タップ以内。

### 見直し・印刷
- [ ] 見直しタブの見出しに「予定時間ベース」「職員の評価には使いません」が常時出る。
- [ ] 区分×時間帯の図、介護助手等の勤務帯の重なり、ノンコアの枠一覧（役割別・枠別。個人別なし）。
- [ ] 枠一覧の ずらす・任せる・減らす が動く。
- [ ] 分担表（A4横）と自分の予定（A4縦）が印刷できる。

### 表現・データ
- [ ] 「人手不足」「不足」「未実施」「完了率」「実施中」の語が UI に無い（`npm run check:wording` が通る）。
- [ ] 実在の利用者・職員・人物の名前を含まない。架空データのみ。
- [ ] 業務日と夜勤の MVP 制限が README に明記されている。
- [ ] 再読み込み時の保存方式（ブラウザ内保存・サンプルに戻す）と同期方式（施設コード）が README に明記され、動く。
- [ ] 製品内に外部AIの呼び出しが無い（依存と環境変数にも無い）。

### 品質
- [ ] `npm run lint` / `npm run typecheck` / `npm test` / `npm run e2e` / `npm run check:wording` が通る。
- [ ] Lighthouse アクセシビリティ 90 以上（ボード・マイナビ）。
- [ ] 押せる領域 44px 以上、文字のコントラスト 4.5:1 以上。
- [ ] キーボードだけで割当・取消ができる。

## 2. E2E シナリオ（Playwright）

### S1 サンプル3操作
1. トップで「サンプル施設で試す」。
2. ボードの「入浴介助 10:30」に「担当あと1人」が出ている。
3. パレットの「鈴木」をカードへドラッグ（またはカードの「＋ 担当を追加」→ 候補「鈴木」→「追加」）。
4. バッジが消え、トースト「鈴木さんを「入浴介助 10:30」に割り当てました」。
5. 「元に戻す」でバッジが戻る。
計測: 1→4 の操作数 3、所要 30 秒以内（初見の目安は試用で測る）。

### S2 朝の流れ
1. 「朝の準備」を開く。
2. 出勤者の役割が既定で入っている。「渡辺」を「休み」にする。
3. 型「入浴日」を選び「この型で今日の時間割を作る」。
4. 「できました」に「担当未定 2（リネン回収、物品補充）」「担当あと1人 1（入浴介助）」。
5. 「ボードで直す」でボードへ。該当カードが強調されている。

### S3 クイック操作「付き添い・外出」
1. スマホ幅で「きょうの全体」を開く。
2. 「付き添い・外出」→ 田中様／受診の付き添い／10:30–12:00／鈴木。
3. プレビューに「追加」「外す（重なるため）」と、結果の「担当あと1人」が出る。
4. 「適用する」→ 一覧に受診の付き添いが現れ、休憩①に「担当あと1人」。
5. 「元に戻す」で全行が戻る。

### S4 スマホ反映
1. タブA: ボード。タブB: マイナビ（佐藤）。
2. タブA で佐藤を「レク準備 14:00」に割り当てる。
3. タブB の「きょうの流れ」に 14:00 レク準備 が 2 秒以内に現れる。
同期環境では、タブB を別端末（施設コードで参加）に置き換えて同じ確認を行う。

### S5 業務詳細（初回の方）
1. 共有端末モードで「加藤」に切り替える。
2. 「口腔ケア 13:00」を開く。
3. 「あなたにお願いすること」「お願いしないこと」「相談先（PHS）」が表示される。対象者は「部屋番号＋姓」。
4. 「実施」「完了」のボタンや語が無い。

### S6 印刷
1. 職員ビューで「分担表を印刷」→ 印刷プレビューが A4 横 1 枚に収まる（`page.emulateMedia({media:'print'})` でレイアウト確認）。
2. マイナビで「自分の予定を印刷」→ A4 縦 1 枚。

### S7 表現チェック
- 全画面のテキストに禁止語が無いことを `check:wording` のスナップショットで確認。
