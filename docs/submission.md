## 一言で

介護現場の一日を「業務の時間割」にして、必要な仕事に人を当て、一人ひとりに「いつ・どこで・誰に・何を」を手元で案内する道具。介護記録ではなく、介護業務のナビゲーション。製品の中で AI は使わない（Claude Code で作った、AI を使わない道具）。

## 課題

介護現場の「今日の仕事」は、慣れた人の頭の中と口頭にある。ユニット型の施設では 1 ユニットの職員が数人と少なく、「この時間に何をするか」「誰（利用者）にどんな注意が要るか」が、初めて来た人（他ユニットからの応援・新人・スポットの経験者・介護助手）には見えない。担い手が多様になるほど、仕事の見える化が前提になる（介護職員の必要数は 2040 年度に約 272 万人、厚生労働省の推計）。

## 解決

人に仕事を積むのをやめて、仕事に人を付ける。

1. **一日を一枚の時間割に。** 縦が時間、横がユニット・フロア・共通。個別・一括・共通・休憩を同じ画面に置き、各枠に施設が決めた必要人数を持たせる。足りない枠だけ「担当未定」「担当あと n 人」と文字で出る（人手不足とは言わない）。
2. **朝は 1 タップ。** 業務は番（早番A・日勤B・介護助手…）に束ねてあるので、先週の同じ曜日の番で「この内容で作る」を押すだけ。介護助手が休みの日は、その番の枠がそのまま「担当未定」で見える。
3. **変更は 3 タップ、フロアのスマホで。** リーダーの「全体」から、付き添い・外出、欠勤・早退を「ボタン → 選ぶ → この内容で決定」。重なる休憩は消さずに後ろへずらす。どの操作も「元に戻す」で戻る。
4. **手元に段取りを。** 応援・新人のスマホに、いまの時間の予定、お願いすること／しないこと、対象の方（お一人ずつの注意）、物品、手順、困ったときの相談先。初日から段取りで迷わない。
5. **「終わった」の印。** 枠ごとに 1 タップで付け外し。時刻が過ぎただけでは付かない。誰が付けたかは画面に出さない。終わりの時刻を過ぎて印の無い枠は「終わっていない n 件」としてリーダーに見える。
6. **業務の見直し。** 区分（コア／ノンコア）×時間帯の予定時間と、介護助手等の勤務帯との重なり。数字は業務に付け、人には付けない。判断は人がする。

## Claude Code の使い方（開発の進め方）

- **憲法を書いてから作る。** `CLAUDE.md` に目的・範囲・判断の原則・表現の規則・データの原則を置き、迷ったら戻る。
- **役割を分けたエージェント。** 範囲と表現の番人、介護現場の目、初見の人（新人／初回の応援／リーダー）、アクセシビリティ、実装、テスト、架空データ。レビュー担当にはファイルを書き換えさせず、4 つを並列に走らせて指摘を 1 つの表にしてから直す。
- **レビューループを 8 回。** 画面を足した日のうちに回し、記録を `docs/reviews/` に残す（修正と「対応しない理由」を両方書く）。
- **決定記録 10 本。** 範囲・画面と押す回数・AI を使わない・同期・「終わった」の印など。覆すときは新しい番号で。
- **表現の規則を機械で守る。** 「人手不足」「完了率」「実施中」などの禁止語を、保存のたびのフックと CI で止める。
- **現場の聞き取りで前提を改めた。** 開発の途中で介護現場の方に聞き、「朝に業務を人へ振る場面は無い」「終わった／終わっていないを 1 タップで」を決定記録 0010 として実装に反映した（内容は要約だけ。引用はしない）。
