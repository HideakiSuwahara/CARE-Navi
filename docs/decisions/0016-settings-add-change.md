# 0016 設定を「はじめに／追加・変更／ふだんの設定」に整理し、施設の名前・グループ・番を足す・直す場所を作る

- 日付: 2026-11-06
- 状態: 決定。同日に実装
- 置き換える決定: 0003 §10「設定は 2 項目」（0011・0015 で 3 項目に広がっていた）→ 設定は「追加・変更」と「ふだんの設定」の 2 つの区画。CLAUDE.md §1 も同じ
- 関連: 0001・0003（業務の種類と業務表の編集画面は作らない。そのまま）、0013（日課は利用者の画面）、0015（職員・勤務表）、グリル `docs/grills/2026-11-06-settings-add-change.md`

## 背景

作者が公開版の設定を触り、「はじめに の他に追加・変更の項目を付けて、すべての設定の追加変更ができるようにしたい。ユニットの追加の個別設定が見つからなかった」。調べると、施設の名前・グループ（ユニット・フロア）・番（役割枠）を、施設を作ったあとに足す・直す場所が無かった（「自分の施設で始める」の最初の 1 回だけ）。

## 決定

1. **設定の区画**: 施設がないときは「はじめに」（3 ボタン）。施設があれば「追加・変更」（施設の名前・グループ・番・職員・名簿の貼り付け・月の勤務表）と「ふだんの設定」（利用者名・初回の警告・施設コード・データの備え）、最後に「はじめから」。
2. **全部を設定に集めない。** 利用者・日課は利用者の画面、業務表はボードの ⋯ に場がある。設定には「ほかの画面で直すもの」としてリンク 1 行ずつ（1 画面 1 目的。二重の編集画面を作らない）。
3. **グループを足す**と、選んだ種類（ユニット／フロア。名前に「ユニット」があればユニットを既定にし、人が選び直せる。ループ 13 で追記）の雛形の番と業務表の枠を写す（「自分の施設で始める」と同じ考え方。`addGroupEvents`）。番の名前はグループ名で付け直し、リーダーの順は写さない。まだ作っていない日の時間割から出る（作ってある日は変えない）。名前を変えると、名前（または「東」のような短い名前）を含む番も付け直す。種類は名前を変えても変えない（ループ 13）。外した番が過去の勤務表にだけ残るとき、先週・前の日の写しではその人を休みで並べ、番を選び直してもらう。職員の所属は職員の欄で直す（ループ 13）。利用者・職員の所属が残る間は外せない（理由を一文）。外せるときは番と業務表の枠も一緒に外す。
4. **番を足す・直す・外す**: 名前・時刻（翌9:00 の書き方）・グループ・リーダーの順。時刻を変えても、入れてある勤務表の時刻は変えない（次に貼る勤務表と、朝の帯で選び直した日から効く）。今日以降の勤務表か業務表で使われている番は外せない（理由を一文）。見直しの勤務帯（reviewBand）はここでは触らない（0008 の範囲）。
5. **施設の名前**を直せる（`facility.set`）。
6. どれも 1 操作 1 バッチで元に戻せる。新しいイベントは無い。

## 理由（お客さん優先の順）

1. 今日のリーダー: ユニットの増減・番の名前の違い（「A勤」）が、施設を作り直さずに直せる。設定に来れば「どこで直すか」が分かる。
2. 応援・職員: 変わらない（番の名前が施設の言い方になるので、朝の帯と自分の予定の表記が合う）。
3. 施設長・委員会: 施設の構成の変更を、名簿を貼り直さずに反映できる。
4. 開発・工程: 既存のイベントと、雛形を写す既存の処理の再利用。
