# 0018 サンプル施設の時計を 10:12 から進め、審査員向けの案内はサンプルのときだけ出す

- 日付: 2026-11-06
- 状態: 決定。同日に実装
- 関連: 0003（最初の画面と押す回数）、0013（開く日。サンプルは基準日 11/3）、グリル `docs/grills/2026-11-06-judge-first-touch.md`

## 背景

作者の依頼で、素人の審査員の目線で巡回した（介護を知らない人が公開 URL を開いて 10 分）。画面だけで 7〜8 分あれば価値は伝わるが、最初の 3 分では「シフトのガントチャート」止まりだった。サンプルの日付は 11/3 に固定なのに時刻は端末の実時刻なので、夜や朝に開くと現在時刻の線が出ず、見せ場（入浴の「担当あと1人」）も画面の外にある。入浴の「＋」では空いている人が 0 人、次の日の「この内容で作る」の直後に夜勤が空になる。

## 決定

1. **サンプル施設の時計**: サンプル施設を開いていて URL に ?now が無いとき、時計は開いた瞬間を 10:12 として実時間で進む（現在時刻の線も進む）。ボードの日付の横は「サンプル施設の一日」とし、「更新 hh:mm」は出さない（操作の時刻は端末の実時刻で残るため）。?now は今どおり固定（E2E・撮影）。
2. **案内はサンプルのときだけ**（作者の答え: 「実際に使うときも、使う人の参考になる」）。スマホの名前一覧の「試すなら」とリーダーの札はサンプル施設のときだけ。最初の画面（/）はサンプルの入口なので、3 つの場面（朝 1 タップ／途中 3 タップ／初日の人のスマホ）と「しないこと」1 行を出す。
3. **道具の説明は常に**: 使い方の先頭に「ケアナビとは」、業務の見直しの見出しの下に 1 文。
4. **サンプルデータ**: 入浴介助の時間に空いている入浴担当可の人を 1 人（休憩の時刻の自然な直しで。人数は盛らない）。次の日以降にも夜勤を含む勤務表。
5. README 冒頭・提出文・動画の筋を、実装とデータに合わせて書き直す。

## 理由（お客さん優先の順）

1. 今日のリーダー: 変わらない（自分の施設は端末の今日・実時刻のまま）。
2. 応援・新人: 変わらない。
3. 施設長・委員会: 導入前にサンプルで試す人が、いつ開いても同じ一日を見られる。
4. 審査員: 最初の 10 秒で現在時刻の線と見せ場が画面に入り、案内から「初日の人のスマホ」へ 1 タップで届く。

## 失うもの

| 失うもの | 置き換え | 評価 |
|---|---|---|
| サンプルで実時刻を見ること | ?now で任意の時刻 | 許容 |
| サンプルの「更新 hh:mm」 | 「サンプル施設の一日」 | 許容 |

## 見直す条件

- サンプルの一日を別の時刻から見せたい（例: 朝の帯から）→ 開始の時刻を選べるようにする。
