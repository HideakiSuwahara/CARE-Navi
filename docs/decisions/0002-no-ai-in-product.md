# 決定記録 0002: 製品内でAIを使わない

日付: 2026-11-02
決定: **ケアナビ本体はAI（外部の生成AI・音声認識を含む）を使わない。** 開発は Claude Code で行うが、できあがる道具は決定的・説明可能・オフライン可で、施設のデータを外部へ送らない。
置き換える決定: 0001 の Q2、必須スコープ 7（自然文による変更入力）・8（棚卸しの下書き）、余力（手順書の下書き・音声入力）、日程 11/5。

## 理由（お客さん優先の順）

1. **個人情報**: 自然文による変更入力は、利用者名・職員名・予定を外部APIへ送る。施設にとって最初に止まる点で、匿名化しても導入の説明負担になる。使わなければ、データは施設が選んだ保存先（ローカル／自施設の施設コード）から出ない。
2. **信頼の分かりやすさ**: 「AIは配置に一切関与しない。決めるのは人」という一文で説明が終わる。「下書きだけ」「提案だけ」という線引きの説明が要らない。
3. **止まらない**: APIキー・課金・遅延・タイムアウト・保存済み応答のフォールバックが全部不要。詰所のPCがオフラインでも、スマホの電波が弱くても同じに動く。
4. **工程**: 約1.5日分を核の品質とレビューループに回せる。11/6 正午の機能凍結に余白ができる。
5. **思想との一致**: 「仕事に人を付ける」は、人の判断を道具が支える話。判断の入口に生成AIを置くと、発表でも現場でも「結局AIが決めるのか」という誤解の芽になる。

## 失うものと、置き換え

| 失うもの | 置き換え（決定的な機能） | 評価 |
|---|---|---|
| 自然文による変更入力 | **クイック操作**を「プレビュー→適用」部品で: ①出勤者の「欠勤・早退」（その人の全担当を外し、空いた枠を一覧で見せる） ②「付き添い・外出を追加」（利用者・時間・担当を選ぶ→重なる担当の解除案と空く枠をプレビュー→適用） ③「休憩をずらす」 ④長押しメニュー（中止・ずらす・担当を外す） | 10〜15秒。自然文より確実で、入力ミスの行き先が見える |
| 棚卸しの下書き（文章→型） | **プリセット約20種**＋**施設種別の一日の型**（従来型／ユニット）＋業務の**貼り付け取込**（名称・時刻・区分・役割を表で貼る） | 典型的な施設は型を当てて直すだけ。独特な日課の施設は手入力が増える（許容） |
| 手順書の下書き | プリセットに手順・物品・相談先の雛形を同梱。施設が書き換える | 十分 |
| 音声入力（ブラウザ音声認識） | 作らない（音声も外部送信になる） | 一貫性のため外す |

## 審査上のリスクと扱い
- ハッカソンは "Built with Claude Code" を掲げる。製品内での Claude 利用は要項で必須とされていない。ただし審査員によっては製品内AIを期待する可能性がある。
- 扱い: 提出文と動画で **「Claude Code で作った、AIを使わない道具」** を明示する。開発過程（構想→10の問い→独立レビュー→決定記録→実装→3ペルソナのレビューループ→テスト）を `docs/` に残し、それが「Built with Claude Code」の中身であると語る。製品の説明は「AIは配置に関与しない」で統一。
- README に「AIの境界」節を置く: 本体は使わない。将来、施設が明示的に有効化する任意モジュールとして、利用者名を含まない文章（業務の棚卸し）に限った下書き支援を検討する余地があることだけ記す。今回は作らない。
