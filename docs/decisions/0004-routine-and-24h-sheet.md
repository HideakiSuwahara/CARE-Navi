# 0004 施設の日課と利用者の24時間シートから、時間割を作る

- 日付: 2026-11-03
- 状態: 決定
- 関連: 0001（スコープ）、0003（画面を5つ・押す回数を最少に）
- §7 の「⋯ → 今日の時間割を作り直す」は 0005 で置き換え（作らない）

## 背景

- 利用者を登録する画面がなかった。業務表（一日の型）だけでは、利用者ごとの生活の流れ（起きる時間、排泄の時間など）を持てない。
- ユニットケアでは、利用者ごとの24時間の生活の流れ（24時間シート）を作り、それに沿って支援する。24時間シートを運営基準で義務とする公的な根拠は確認できなかったが、研修と現場で標準的に使われる道具であり、ユニットケアの考え方（職員のペースや日課の消化ではなく、その方の生活習慣に沿う）そのものである。
- 一方で、24時間シートだけを時間割の基準にすると、利用者にひも付かないノンコア業務（リネン回収・物品補充など）が割り当てられない。従来型では、全員分を一人ずつ作るのは負担が大きい。
- 個人の一日の画面は細かく分かりやすいが、その中身を「誰が毎日入力するのか」が問題になる。

## 決定

### 1. 業務の出どころは3つ。毎日入力するものは作らない
| 出どころ | 中身 | 誰がいつ |
|---|---|---|
| ① 施設の日課 | 利用者全員（グループ全員）にかかわる業務と標準の時刻（起床・食事・排泄・おやつ・就寝など） | 施設が最初に一度 |
| ② 利用者ごとの調整（24時間シート） | ①との違いだけ（時刻の変更・その方はなし・その方だけの行）と、生活リズム／意向・好み／自分でできること／サポートが必要なこと | 入居時・ケアプランの見直し時に、違うところだけ |
| ③ 施設の業務（業務表） | 利用者にひも付かない業務（見守り・リネン回収・物品補充・食堂準備・休憩など） | 施設が最初に一度 |
毎日は「出勤者に番を付ける」だけ（0003）。個人の画面は①〜③を自動で組み立てる。

### 2. 時間割への入り方（枠の中なら一括のまま、枠の外なら別の枠）
施設の日課ひとつ（例: 東フロア 起床介助 7:00–8:00）について、対象の方を分ける。
1. 標準どおりの方 → 一括の枠（「起床介助 19人」）。
2. 時刻を変えた方で、変えた開始時刻が枠の中 → 一括の枠に入れたまま。詳細の対象者一覧にその方の時刻を出す（「山田様 7:30」）。
3. 枠の外に変えた方 → 別の枠を作る（「起床介助 田中様 8:30」）。同じ時刻に変えた方が複数いれば1枚にまとめる。
4. 「この方はなし」→ その日課の枠に入れない。
- どの方も、一つの日課につき必ず一つの枠にだけ入る（二重に数えない）。
- 別になった枠は、元の日課と同じ番に束ねる。必要人数は業務の種類の標準（多くは1人）。
- 24時間シートで足した「その方だけの行」に業務の種類が付いていれば、その方の個別の枠を作る。業務の種類が付いていない行（「10:00 新聞を読む」など）は、シートと手元画面の参考にだけ出し、枠は作らない。

### 3. 登録の初期値は「全員が標準どおり」
- 名簿を貼り付けた時点で全員に施設の日課が当たる。従来型はこれで時間割ができる。
- 利用者画面の「一覧」（縦に利用者、横に日課）で、標準と違うマスだけ直す。複数の方を選んでまとめて時刻を変えられる。
- 「24時間シート」（一人ずつ、縦に時刻）で、時刻と4つの項目を書く。ユニット型は最初からこちらで作ってもよい。
- 一覧と24時間シートは同じデータの見え方の違い。

### 4. サポートが必要なことは、担当の人に出す
業務詳細の「対象の方」に、方ごとに1行（時刻とサポートが必要なこと）を出す。出すのは、その業務の担当の人に、勤務時間中だけ。名前は手元画面の表示名の設定に従う。0001 Q7 の「利用者ごとの介助方法は載せない」を、この1行に限って改める。

### 5. 24時間シートの書き出し
- 利用者ごとに A4 縦で印刷（時刻／生活リズム／意向・好み／自分でできること／サポートが必要なこと）。
- CSV（Excel で開ける）で、24時間シートと一覧を書き出す。

### 6. 画面
PC に「利用者」画面を足す（中に［一覧｜24時間シート］）。PC のナビは「ボード／利用者／業務の見直し／設定」。画面は6つになる（0003 §1 を改める）。

### 7. 時間割を作ったあとにシートを直したとき
シートの変更は、次に時間割を作るときから反映する。その日に反映したいときは、ボードの「⋯ → 今日の時間割を作り直す」（確認つき）。当日の受診などは、これまでどおりクイック操作で入れる。

### 8. 日程のために削るもの
- 業務の見直し: 図1枚とノンコアの枠一覧だけ（「見直す ▾」の操作は作らない）。
- 同期: Supabase の端末間同期はやめ、同じ端末（同じブラウザの別タブ）の即時反映だけにする。動画の字幕で明示する。本番の要件として README に書く。
- クイック操作: 付き添い・外出と、欠勤・早退の2つ（休憩をずらすは、カードの「⋯ → ずらす」で代える）。

## 影響
- データ: DayPatternItem / TaskInstance に `routineId`、TaskInstance に `targetTimes`（方ごとの時刻）、利用者ごとの `ResidentSheet`（行の配列）と `sheet.upsert` イベント。`applyPatternEvents` が 2. の規則で枠を作る。
- サンプルデータ: 業務表の利用者にかかわる項目に `routineId`、数名の時刻変更（枠の中と枠の外）、さくらユニットの方は24時間シートの文章を丁寧に。
- 画面仕様（docs/screens.md）に「利用者」画面を足し、業務詳細の「対象の方」にサポートの1行を足す。

## 採らなかった案
- 24時間シートだけを基準にする: ノンコア業務が割り当てられず、従来型の登録が重い。
- 時刻を変えた方を、少しの違いでも別の枠にする: ボードが小さなカードだらけになり読めない。
- シートを直したら当日の時間割も自動で変える: 当日の担当がいつの間にか変わり、現場が混乱する。
