## 判断の原則

1. **お客さんの順番**: ①今日のリーダー（分担を決め、変更を入れる人） ②応援・スポット・新人・介護助手（手元で確認する人） ③施設長・委員会（配置を見直す人） ④審査員。衝突したら番号の小さい方。
2. **初週に①が使うものだけを必須**。③向けは「見直し」タブ1枚まで。
3. **変更は10秒以内、フロアのスマホで**。どの変更経路も「3タップ以内」。PCの前に戻らないと変えられない道具は死ぬ。
4. **朝は「人に役割を付ける」だけ**。業務は役割（早番A・日勤B・介護助手…）に束ねておき、朝は「今日のA番は誰」を決めるだけで全枠に担当が付く。これが「仕事に人を付ける」の実装形。
5. **数字は業務に付ける。人には付けない**。生産性の見える化は配置の見直しのため。職員個人の区分別時間は出さない（役割別まで）。日次画面には置かない。
6. **入力の省力化はプリセット・型・クイック操作で行う**（0002 により AI は使わない）。判断・配置・適性は人。
7. **言わないことは言わない**（人手不足／未実施／完了／できる・できないの断定）。動画でも同じ。創作した「現場の声」は使わない。**個人名は一切出さない**。
8. **D&Dは職員チップの割当だけ**。時刻変更はメニュー（±15/30/60分・時刻入力）。
9. **11/6（金）正午に機能凍結**。以降は修正・レビュー・動画のみ。

## 10の問いへの回答と、製品への反映

### Q1 「カレンダーに職員チップを付けただけでは？」施設がやめられること
**答え**: カレンダーは予定を並べる道具で、「この枠に何人必要で、いま何人いるか」を持たない。ケアナビは業務の枠に必要人数を持たせ、埋まっていない枠を見せ、埋めた結果を本人の手元に届ける。多くの施設には役割表と、毎朝ホワイトボードに書く分担がある。ケアナビはその役割表を「今日の人・今日の利用者」に合わせて毎日組み直せるようにしたもの。
**施設がやめられること**: 毎朝の分担の手書き、応援への口頭の一日説明（段取り部分）、「誰か入れる？」の探し電話。
**反映**: 役割枠（RoleSlot）の導入。「分担表を印刷」（職員ビューのA4横）。すべての業務枠は必要人数を持ち、充足差分がボードの見出し指標。

### Q2 AIが脇役。「介護の判断は人」は逃げか
**答え（0002 で更新）**: 施設はAIが配置や適性を決めることを受け入れない。当初は「1日に10回起きる変更の入力」に自然文の下書きを使う案を採ったが、個人情報の外部送信・信頼の説明負担・停止リスクを理由に、製品内でAIを使わないことにした。変更の入力は、決定的なクイック操作（欠勤・早退／付き添い・外出／休憩をずらす）と長押しメニューで10秒以内にする。

### Q3 効果は未検証。実在の人に触ってもらえるか
**答え**: 11/6（金）夕〜11/7（土）に、実在のリーダー1〜3人にサンプル施設のリンクを15分触ってもらう（ログイン・入力不要なのはこのため）。測るのは「初見で『担当あと1人』を解消するまでの時間」と「迷った箇所」。言葉は本人の了解を得た範囲だけ使う。創作した声は使わない。動画の効果表現は「仮説」＋「初見試用の実測（n=◯）」に限る。設計思想は特定の個人に帰属させず、本プロジェクトのものとして語る。
**反映**: `docs/usability-script.md`。サンプルモードに「初回割当までの時間」をローカルだけに記録して試用者が見られる表示（送信しない）。

### Q4 時間割を誰が維持するか。10:05の発熱でリーダーは何を取るか
**答え**: PHSを取る。ケアナビは10:05の瞬間の道具ではない。使われるのは3つの瞬間。①朝の1〜2分（出勤者に役割を付ける→型を当てる→例外だけ直す）、②変更が決まった直後の10秒（電話を切ってから、フロアのスマホでクイック操作か長押しメニュー）、③本人が手元で見る随時。②が10秒を超えると時間割は古くなって死ぬ。古くなったボードが「嘘」にならない設計も必要。ボードは実施中・完了を推定しないので、古い時間割は「予定が古い」だけで、起きたことを偽らない。
**反映**:
- カード長押し／右クリックの即時メニュー「中止」「ずらす」「担当を外す」（2タップ）。スマホでも同じ。
- リーダーのスマホにも「きょうの全体」（グループ別の時間順リスト、充足バッジ、長押しメニュー、クイック操作）。
- ボード右上に「更新 10:07」（時刻のみ。誰が変えたかは履歴パネル）。
- 休憩を時間割のカードにする（休憩①②③、必要人数あり）。「休憩中」チェックはこのカードを参照する。
- 「今日の出勤者」＝名前をタップ→役割を選ぶ。役割が勤務時間を持ち、個別に直せる。勤務パターンは施設で編集可（既定8種）。勤務表ソフトからの取込は作らない。
- 説明は「朝1分と、変更10秒」に統一。

### Q5 夜勤はユニット2つに1人。「担当未定」だらけになる
**答え**: 夜勤帯の価値は「割り当てる」ことではなく、夜勤専従・派遣・応援が夜の段取りを手元で持てること。配置は役割枠で片付く（夜勤(東)の業務は夜勤(東)の人に付く）。残った「必要2・配置1」は、夜間の2人介助がどれだけ1人で行われているかという事実で、委員会が見る材料（施設が必要人数を2と決めた枠の差分。人手不足とは言わない）。
**反映**: 追加機能なし。翌6:00までの表示。サンプルに夜勤帯を入れる。動画では見せない。

### Q6 「介護福祉士のノンコア90分」が見えても動かせない。責める材料になる
**答え**: 数字を人に付けない。ノンコアの枠一覧（「リネン回収 30分 10:00 役割: 日勤A」）として見せ、1枠ごとに「ずらす・任せる・減らす」の3動作に直結させる。介護助手が週3午前のみなら「介護助手の勤務帯」を重ねて表示し、枠の時刻を勤務帯の中へ動かすことが明日の行動になる。役割枠のおかげで、介護助手が休みの日は束ねた枠がそのまま「担当未定」として朝に見える。
**反映**: 職員個人の区分別時間は表示しない。見直しタブ（週）へ分離し、日次ボードの隣には置かない。見出しに常時「予定時間ベース」「配置を見直すための数字で、職員の評価には使いません」。

### Q7 応援の私は、この画面で何ができて何ができないか。「迷わない」とは
**答え**: 迷わないのは段取り（いつ・どこで・誰と・何を持って・誰に聞く）。できないのは利用者ごとの介助方法の判断。それは施設の記録と、同じ枠にいる常勤が担う。
**反映**: 業務詳細の最上段に「あなたにお願いすること／お願いしないこと」。対象者一覧の下に「利用者ごとの介助方法は、相談先に確認してください」。出勤者に「初回」の印を付けられ、枠の担当が初回の人だけなら「初回の方だけの配置です」の警告（施設でOFF可。応援・スポットという属性では判定しない）。文言は「一人でできる」ではなく「初日から、段取りで迷わない」。

### Q8 私物スマホに利用者20人の実名。帰り道にも残る
**答え**: 施設は許さないことが多い。表示名を施設が選べる（フルネーム／部屋番号＋姓／部屋番号のみ。手元画面の既定は部屋番号＋姓）。私物禁止の施設向けに共有端末モード（詰所のタブレットで名前を選ぶ）と「自分の予定を印刷」。本番は端末に残さない設計（サーバー保持＋認証）と README に明記。デモは架空データ。
**反映**: 施設設定 `residentDisplayMode`。職員切替を共有端末モードとして製品機能に昇格。マイナビの印刷表示。

### Q9 ローカルファーストは同一ブラウザしか同期しない。動画で"つながって見える"のは誠実か
**答え**: 誠実ではない。お客さんにとっては、リーダーのPC・スマホと職員のスマホがつながらない時点で製品ではない。同期を必須に戻す。ただし打ち切り日と縮退経路を今決める。
**反映**: 保存層はイベントログ＋リデューサ。2実装（ローカル＝ブラウザ内保存／同期＝Supabase の `events` 1テーブル＋施設コードで絞った Realtime 購読、QRで参加）。打ち切り 11/5（木）正午。通らなければ同一ブラウザで撮影し、字幕で「同一ブラウザ内のデモ」と明示。通れば字幕は「施設コードで同期（デモ）／本番は認証と権限」。Supabase 無料枠は7日無操作で停止するため、審査期間中に一度は触る。

### Q10 1週間で何を捨てるか。3分に見直しは要るか
**答え**: 「次に検討」を全部作ろうとしていた。捨てる。3分に見直しタブは15秒だけ（図1枚）。簡易実施記録は今回作らない（介護記録ソフトや紙と二重入力になり、初週のリーダーは使わない）。型（CareRecord）は設計だけ残し、ハッカソン後に判断する。

## スコープ確定（0002 反映後の最終形は concept.md §8）

### 必須（11/6 金 正午までに揃える＝機能凍結）
1. 基盤（型、イベントログ＋リデューサ、ローカル保存、チェック関数＋単体テスト、プリセット業務約20種、役割枠の既定8種）
2. ボード（縦=時間、横=グループ／職員の切替、現在時刻ライン、個別・一括・共通・休憩、充足バッジ、更新時刻、翌6:00まで表示）
3. 割当（職員チップの D&D、タップ候補（理由付き3段）、Undo（履歴10手）、警告、二重登録禁止）
4. 即時メニュー（中止・ずらす・担当を外す）
5. 朝の流れ（今日の出勤者→型を当てる→例外を直す。「今日を型として保存」。型の編集画面は作らない）
6. マイナビ（いま／つぎ／きょう、業務詳細、共有端末モード、表示名設定）、リーダー向け「きょうの全体」
7. ~~ひとこと変更~~ → クイック操作（0002）
8. ~~棚卸しアシスタント~~ → プリセットと型（0002）
9. 同期（施設コード＋Realtime＋QR参加）。ローカルはサンプル用。打ち切り 11/5 正午
10. はじめの設定（「サンプルで試す」／自分の施設 3ステップ）
11. 見直しタブ（図1枚: 区分×時間帯、役割別、介護助手等の勤務帯、ノンコア枠一覧と3動作）
12. 印刷（分担表、自分の予定）
13. テスト（チェック関数・バッジ文言の単体テスト、受け入れシナリオの E2E）
14. 配布（Vercel。README はこの製品のことだけ。LICENSE。環境変数は Supabase の2種）

### 余力（必須が全部緑のときだけ）
- 休憩・見守りの型の既定を施設種別（従来型／ユニット）で切替

### 作らない（今回）
- 簡易実施記録、記録一覧・CSV・印刷、対象者別の記録、完了率
- カードの上下ドラッグによる時刻変更（メニューで代替）
- 一日の型の編集画面、勤務表ソフトからの取込、CSVファイル取込
- 一括枠からの個別切り出し、対象者別担当、日をまたぐ予定移動
- 認証・権限（施設コードで代替。本番要件として README に記載）
- 写真・動画・通知・帳票、外部連携、自動配置、必要人数の推定

## サンプル施設と動画の筋
「ひまわり苑」（架空）: 東フロア（従来型20人）、さくらユニット（10人）、共通。職員12人。役割枠は早番A/B、日勤A/B/C、日勤（さくら）、遅番、夜勤(東)、夜勤(さくら)、介護助手、看護、スポット。型「平日」「入浴日」各60枠前後。見守り（フロア担当）は2時間刻みの継続カード。休憩3波。おむつ交換は一括（対象者一覧を開いて見せる）。

穴の置き方: 従来型でおむつ交換を「5人中4人」とは数えない。本物の穴は ①入浴の専従が1人足りない ②受診付き添いでフロア担当が空く ③昼休憩帯の見守り。動画はこの3つで組む（docs/video-storyboard.md）。

## レビューで変わったこと（草案→本版）

| 観点 | 草案 | 本版 | 理由 |
|---|---|---|---|
| 朝の流れ | 前日コピー→直す | 出勤者に役割を付ける→型を当てる | 昨日の業務は写せても昨日の人は今日いない。60枠にチップを置き直すと30分で紙に戻る |
| 休憩 | 勤務の属性 | 時間割のカード（3波・必要人数） | 誰をいつ下げるかは毎日の判断 |
| 変更の場所 | PCのボード | フロアのスマホ（きょうの全体＋クイック操作） | リーダーは10時台フロアで手袋をしている |
| 更新表示 | 「更新 10:07 ◯◯」 | 時刻のみ、名前は履歴 | 犯人探しに見える |
| 業務構成 | 日次画面 | 見直しタブ（週） | 日次ボードの隣にあると評価の棒に見える |
| 応援警告 | 応援・スポット属性 | 「初回」の印 | 他ユニットからの応援は常勤。一律素人扱いになる |
| デモの穴 | おむつ交換 5人中4人 | 入浴あと1人／受診付き添いで見守りが空く | 従来型はおむつ交換を全員でやる |
| 勤務パターン | 4種 | 8種・施設で編集 | 早出・短時間・遅番が足りない |
| 簡易記録 | 余力 | 今回作らない | 二重入力で初週に使われない。工程の余白も無い |
| 時刻変更 | カードの上下ドラッグ | メニュー | タッチ対応の負債 |
| 保存層 | 正規化テーブル | イベントログ＋リデューサ | 同期を半日に圧縮、Undoが同期と両立 |
| 同期 | 必須 | 必須＋11/5 正午打ち切りと縮退経路 | 審査員が触るのはサンプル。動画の説得力に効く範囲 |
| 日程 | 11/4・11/5 が各2日分 | 並列化、サンプルデータ専任、配管先行、11/6 正午凍結、11/7 動画専用 | 溢れるとレビューと動画が削られる |
