# 0009 端末間の同期を作る（施設コード＋Supabase）

- 日付: 2026-11-03
- 状態: 決定（0004 §8 の「同期は作らない」を改める）
- 関連: 0001（スコープ）、0004 §8、docs/data-model.md「保存層」

## 決定
- 端末間の同期を今回の提出に入れる。保存層の `DataStore` に `SyncStore` を足す（Supabase の `events` テーブル 1 つ＋Realtime）。画面は `Engine` の `dispatch`／`undo` だけを呼ぶので変えない。
- 既定はいままでどおり**ブラウザ内保存**（サンプル施設はローカルのまま）。設定の「施設コード」で「この施設を同期する（施設コードを発行）」を押すと、その端末のイベント列を施設コードの下に送り、以後はその端末が同期で動く。
- ほかの端末は「施設コードで参加」（コードを入れる、または QR を読む → `/setup?join=コード`）。参加した端末はブラウザ内にキャッシュを持ち、オフラインでも読める。送れなかったイベントは端末に残し、次に送れたときに送る。
- 見出しの「更新 hh:mm」の横に、同期中なら「同期中」、届かないときは「この端末の内容」と出す（screens §0.8）。
- **施設コードは認証ではない。** anon キーで読み書きできる試用の版で、本番では認証・権限・端末にデータを残さない設計が要る（README に残す）。
- 環境変数は `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` の 2 つ。未設定なら同期の項目を出さず、ローカルだけで動く。鍵はリポジトリ・文書・会話に書かない。

## 理由（お客さん優先の順）
1. 今日のリーダー: フロアのスマホで変えた内容が、詰所の PC のボードと、ほかの職員のスマホに同時に映ることが「変更 10 秒」の前提。別タブだけでは実演にならない。
2. 応援・職員: 自分のスマホで「自分の予定」を開ける（共有端末に縛られない）。
3. 審査員: PC とスマホの 2 台で試せる。

## 失うもの・置き換え
| 失うもの | 置き換え | 評価 |
|---|---|---|
| 凍結前の最後の日（持ち越しの修正） | 持ち越しは凍結後の修正ループへ | 同期の方が実演の価値が大きい |
| 「施設コード＝認証ではない」の分かりやすさ | 設定画面と README に明記 | 試用の範囲で使う |
