# 表現の規則

UI・文書・動画・提出文のすべてで守る。`scripts/check-wording.mjs` が禁止語を機械的に検査し、フックと CI で止める。

## 1. 原則
1. **未割り当て ≠ 人手不足。** 示すのは「施設が決めた必要人数」と「割当数」の差分だけ。人手の過不足・採用必要数は断定しない。
2. **記録しないものを断定しない。** 時間が過ぎても「実施中」「完了」「済」にしない。記録機能は持たない。
3. **区分はラベル、可否は条件。** 「介護助手だからできない」「介護職員なら何でもできる」という文言を作らない。条件不一致は「満たしていません（施設の設定）」。
4. **必要人数は施設の予定値。** 対象者数から「適正人数」を計算・表示しない。
5. **数字は業務に付ける。** 職員個人の区分別時間・ランキングを出さない。役割別・枠別まで。
6. **効果は仮説。** 「教育時間が減る」「採用に効く」「ケアの質が上がる」は、未検証と添えるか言わない。
7. **声は創作しない。** 了解を得た実在の発言だけ。無ければ出さない。
8. **個人名は出さない。** 実在の人物・施設の名前は、コード・コメント・文書・動画・提出文のどこにも入れない。設計思想は本プロジェクトのものとして語る。
9. **AIを示唆しない。** 「AIが提案」「自動で最適化」「ひとこと変更」など、製品内でAIが動くかのような語を使わない。

## 2. 使わない語と言い換え

| 使わない | 言い換え | 理由 |
|---|---|---|
| 人手不足／人員不足／不足 | 担当未定／担当あと n 人／必要 n・配置 m | 差分の事実だけを言う |
| 未割り当て（UI上） | 担当未定 | 「未」の重なりを避け、短く |
| 実施中／進行中 | いまの時間の予定 | 記録しないので状態を断定しない |
| 完了／済／終了（業務の状態として） | （出さない。過ぎた予定は薄く表示） | 同上 |
| 未実施 | （出さない。記録機能なし） | 記録なしと混同する |
| 完了率／実施率／達成率 | （出さない） | 分母と未記録の混同を招く |
| 最適化／自動配置／AIが提案／おすすめの配置 | 候補（理由つき） | 決めるのは人 |
| できない／不可／NG（職員について） | 条件「◯◯」を満たしていません（施設の設定） | 役職や属性で可否を断定しない |
| 評価／成績／ランキング（職員について） | （出さない） | 数字は業務に付ける |
| 応援・スポットのみの配置 | 初回の方だけの配置です | 属性ではなく当日の印で判定 |
| 最終更新 hh:mm ◯◯さん | 更新 hh:mm（名前は履歴で） | 犯人探しに見せない |
| 患者 | 利用者／◯◯様 | 介護の語 |
| 業務を消化／こなす | 業務を行う | 人への配慮 |
| 加算が取れる | 加算の要件に向けた下準備になり得る | 保証しない |

## 3. 時刻・人の表記
- 時刻は `10:30–12:00`。翌日は `翌2:00`。
- 利用者は「田中様」（ボード）／「203 田中様」（手元画面の既定）。
- 職員は名字＋「さん」を会話文で、チップでは名字のみ。
- 一括は「20人」、共通は「対象なし」または「共通」。

## 4. バッジ・候補・プレビューの定型文
- `担当未定` / `担当あと {n} 人` / `{n} 人 多め`。横に「予定の担当枠の差分です」。
- 候補の理由: 「{開始}〜{終了} の『{業務名}{対象}』と重なります」「勤務は {開始} からです」「条件「{タグ}」を満たしていません（施設の設定）」「初回の方だけの配置です」「本日休みです」。
- プレビュー: 「こう変わります（チェックを外すと、その行はしません）」。行頭は `追加` `外す` `中止` `ずらす`。結果行は `担当あと 1 人 — 休憩① が 必要2・配置1 になります`。
- トースト: 「{名字}さんを「{業務名} {開始}」に割り当てました［元に戻す］」「戻しました」。
- 見直しの前提帯: 「予定時間ベース（一日の型と当日の予定から計算。実施時間ではありません）」「配置を見直すための数字です。職員の評価には使いません。」

## 5. 機械チェックの対象（`scripts/check-wording.mjs`）
- 対象: 製品に出る文字列。`npm run check:wording` は `src/**`（テスト含む）と `README.md` を見る。設計文書（`docs/**`）と `.claude/**` は、規則を説明するために語を引用するので既定では対象外（フックが変更ファイルを検査する場合も同じ扱い）。
- 禁止語（部分一致、公開リポジトリに置ける一般語のみ）: `人手不足`, `人員不足`, `完了率`, `実施率`, `達成率`, `自動配置`, `最適化`, `AIが提案`, `ひとこと変更`, `実施中`, `未実施`。
- 例外: 行内に `wording-ok` と理由を含む行は除外する（禁止語を説明するコメントや、禁止語自体を検査するテストで使う）。
- 実在の人名の検査は、公開しない設定ファイル（`.wordcheck.local.txt`、git 管理外、1 行 1 語）に語を置けば、`src/**`・`docs/**`・`README.md`・`.claude/**` を追加で検査する。リポジトリには名前を書かない。
