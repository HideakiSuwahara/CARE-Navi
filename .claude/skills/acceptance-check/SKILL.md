# 受け入れ条件の検証

推測で「満たす」と書かない。動かして確かめたものだけを「満たす」とする。

## 手順

1. `docs/acceptance.md` を開き、条件を番号つきで列挙する（番号がなければ上から振る）。
2. 前提を整える: `npm run lint && npm run typecheck && npm test` を通し、`npm run dev` を起動する。
3. 各条件について、確かめ方を決めてから実行する。
   - 画面の挙動 → Playwright か手動操作（スマホ幅 390px も含む）。可能なら E2E に残す。
   - 純関数の挙動 → `node --test` の該当テストを指す（なければ書く）。
   - 文書に書くべきこと（夜勤の制限、保存方式、本番要件）→ README / docs の該当行を指す。
4. 結果を表にする。

| # | 条件 | 確かめ方（コマンド・操作・ファイル:行） | 結果 | 備考 |
|---|---|---|---|---|
| 1 | 記録を使わずに予定の閲覧・配置・変更ができる | e2e/board.spec.ts「3操作で解消」 | 満たす | |
| 2 | 未割り当てを「人手不足」と表現しない | `npm run check:wording` + 画面の目視 | 満たす | |

結果は「満たす／満たさない／未確認（理由）」の3つだけ。

5. 「満たさない」は、再現手順（最小）と、直すべき箇所の見当を添える。
6. 表を `docs/reviews/` の当日の記録ファイルに貼るか、提出前なら `docs/acceptance.md` の末尾に「検証結果（日付）」として追記する。

## 必ず入る確認（忘れやすいもの）

- 時間が過ぎた予定が「完了」や「実施中」になっていない。
- 一括業務の対象者一覧が開ける。対象者数だけの保存になっていない。
- 同じ職員を同じ業務に二度入れられない。重複・勤務外・休憩・条件は警告して許可。
- 「元に戻す」が、今日の時間割を作る・クイック操作のようなまとまった操作も1回で戻す。
- 再読み込みで状態が残り、「サンプルに戻す」で初期化される。
- 深夜をまたぐ勤務・予定の扱い（翌 6:00 まで、24:00 超えの分）が README に書かれている。
- 見直しの図に「予定時間ベース」「職員の評価には使わない」が出ている。職員個人の内訳が出ていない。
- リポジトリに実在の情報、他プロジェクトの名前、個人名が入っていない。
