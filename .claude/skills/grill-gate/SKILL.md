# グリルしてから改修する（grill-gate）

使い手の目線のレビュー（主任の日常・忘れたときの復帰・審査員の見え方など）で出た改善案は、すぐ実装しない。
決定ツリーを 1 問ずつ潰してから直す。フックがこれを強制する。

## 流れ

1. **案を書く**: `docs/grills/YYYY-MM-DD-短い名前.md` に、案ごとに「困りごと（場面）」「案」を書き、冒頭に `状態: グリル待ち`。
   この時点で `src/` の .ts/.tsx は編集できない（`scripts/hooks/pre-edit-grill.mjs` が exit 2 で止める。テストと docs は止めない）。
2. **グリルする**（`grill-me` スキルの作法）: 案ごとに、上流の決定から 1 問ずつ。問いには必ず推奨案と理由を添える。
   コードで分かることは聞かずに調べる。観点: ゴール（誰が・いつ）／範囲（CLAUDE.md の作らないもの・決定記録に触れないか）／
   押す回数（原則 3）／言葉（wording.md）／データとイベント（新しいイベントが要るか）／空・エラー・忘れたときの次の 1 手／元に戻せるか。
   - ユーザーが会話にいるときは AskUserQuestion で 1 問ずつ聞く。
   - ユーザーから「ノンストップで」と任されているときは、推奨案を採る理由を 1 行で書いて自分で答える（自問自答の記録を残す）。
3. **結論を書く**: 「決まったこと」「決まっていないこと（見送り・後で）」「受け入れ条件（確かめ方）」。
   範囲や表現に関わる決定は `decision-record` で決定記録にもする。
4. **状態を変える**: 進める案がそろったら `状態: 改修可`。全部見送るなら `状態: 見送り`。ここで初めて `src/` を直せる。
5. 直したら記録の末尾に「対応」（コミット・確かめた結果）を足す。

## 記録の書式

```markdown
# グリル: （何の見直しか）

状態: グリル待ち
日付: YYYY-MM-DD
出どころ: （どのレビュー・どの場面）

## 案 1: （短い名前）
- 困りごと: （誰が・いつ・何に詰まったか）
- 案: （何をどうするか）

### グリル
- Q1. （問い）— 推奨: （案と理由）→ 答え: （採った案）
- Q2. …

### 決まったこと ／ 決まっていないこと ／ 受け入れ条件

## 対応
```

## 止めないもの

- バグの修正（`docs/grills/` にグリル待ちがなければ止まらない）。
- テスト（`__tests__`）、docs、scripts の編集。
