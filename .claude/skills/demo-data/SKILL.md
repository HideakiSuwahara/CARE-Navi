# 架空データの作法

サンプルデータは審査員が最初に見る画面そのもの。現場として自然で、実在の情報を一切含まないこと。

## 絶対に守る

- 実在の人名・施設名・住所・電話番号・メールを使わない。似た名前の実在施設を連想させる固有名詞も避ける。
- 利用者ごとの介助方法・排泄状態・疾患・採用品を持たせない（データモデルにも項目がない）。
- 必要人数・所要時間は「この架空施設の設定値」。介護の標準値として書かない。
- 役職から可否を決めない。可否は担当条件タグ（例: 入浴担当可、喀痰吸引、夜勤可）で表す。

## 名前

- 姓は一般的なもの（佐藤・鈴木・高橋・田中・伊藤・渡辺・山本・中村・小林・加藤・吉田・山田・松本・井上・木村・林・清水・山口・森・池田 など）。
- 利用者と職員で姓を重ねない（画面で混ざらないように）。利用者は「姓 名（カタカナ）」、職員は「姓 名（ひらがな）」にすると見分けやすい。
- 表示は利用者「様」、職員は姓のみ（または「さん」）。
- 施設名は「ひまわり苑」で固定（動画・README・テストで一致させる）。

## 構成（ひまわり苑）

| 項目 | 値 |
|---|---|
| グループ | 東フロア（従来型・20人・部屋 101–120）、さくらユニット（10人・部屋 201–210）、共通 |
| 職員 | 約12人: 介護福祉士 4、介護職員 4、介護助手 2（週3・午前のみ）、看護師 1、スポット 1（初回） |
| 番（役割枠） | 早番A・早番B・日勤A・日勤B・日勤C・日勤さくら・遅番・夜勤東・夜勤さくら・介護助手・看護・スポット午後（括弧を使わない） |
| 勤務時間の既定 | 早番 7:00–16:00、日勤 9:00–18:00、遅番 11:00–20:00、夜勤 17:00–翌9:00（1020–1980）、介護助手 9:00–13:00、スポット 13:00–17:00 |
| 業務表（一日の型） | 平日・入浴日（火金）・日曜（weekdays 付き）。50〜60枠。見守りは2時間刻み（ユニットにも）。休憩は波で、勤務時間内・同じ人の重なりなし。職員に任意の PHS |

## 現場として自然にする

- 従来型のおむつ交換はフロアの職員全員で行う（「5人中4人」のような数え方をしない）。
- 入浴は専従が付く。入浴日は入浴介助 6 枠、必要 3。ここが「担当あと1人」になる筋。
- 介護助手が休みの日を 1 日入れる。その日はリネン回収・物品補充など介護助手に束ねた枠が「担当未定」になる。
- 遅番は 11:00 前後から。見守り（フロア担当）が 11:00 で早番から遅番に替わる。
- 夜勤帯は巡視（22:00／0:00／2:00／4:00）、体位変換、起床介助（5:30〜）。1 人体制なので「必要2・配置1」の 2 人介助が事実として残る枠を 1 つ入れてよい。
- 個別予定: さくらの利用者にバイタル測定（看護）、排泄介助、2 人介助の入浴を数件。

## 文言

- 業務名は現場の言い方（排泄介助、おむつ交換、口腔ケア、見守り、水分補給、起床介助、就寝介助、巡視、体位変換）。
- 「お願いすること／お願いしないこと」は 1〜2 文ずつ。手順は 3〜5 行、施設固有の短い言い方。医療的判断を書かない。
- 相談先は「役割＋連絡手段」（例: 一緒に入る職員 PHS 203、きょうのリーダー PHS 201）。
- docs/wording.md の規則に従う。書いたら `node scripts/check-wording.mjs src/domain/seed` を通す。

## 時刻の表し方

- 分は業務日 0:00 起点。翌日分は 1440 を足す（翌 2:00 = 1560、翌 9:00 = 1980）。
- 夜勤帯の業務は、その夜勤が始まった業務日に属する。
